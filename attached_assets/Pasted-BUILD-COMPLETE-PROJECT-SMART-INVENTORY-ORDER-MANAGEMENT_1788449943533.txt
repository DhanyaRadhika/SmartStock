BUILD COMPLETE PROJECT: SMART INVENTORY & ORDER MANAGEMENT SYSTEM

You are an expert full-stack developer and software architect.

Build a complete, polished, production-style college placement project called:

Smart Inventory & Order Management System

The application is a small-business e-commerce and inventory management platform.

Customers can browse products, add products to a cart, place orders using a simple Cash on Delivery option, and view their orders.

Administrators can manage products, inventory, suppliers, orders, low-stock alerts, and reports.

The application must be genuinely functional from frontend to backend to database.

7. GOOGLE OAUTH CONFIGURATION

Use environment variables or your deployment platform's secret store.

Required variables:

GOOGLE_CLIENT_ID
GOOGLE_CLIENT_SECRET
GOOGLE_CALLBACK_URL
SESSION_SECRET

Also use:

MONGODB_URI

Create a .env.example file:

GOOGLE_CLIENT_ID=your_google_client_id
GOOGLE_CLIENT_SECRET=your_google_client_secret
GOOGLE_CALLBACK_URL=your_callback_url
SESSION_SECRET=your_random_session_secret
MONGODB_URI=your_mongodb_connection_string

Never hard-code secrets.

Never expose GOOGLE_CLIENT_SECRET to Angular.

Only the backend can access the Google Client Secret.

8. GOOGLE OAUTH MUST NOT BREAK THE APPLICATION

If Google credentials have not yet been configured:

The application must still start.
Angular must still compile.
Backend must still start.
Do not crash the entire application.
Show a clear message explaining that Google Sign-In requires OAuth configuration.

Once the credentials are added to your deployment secrets, Google login should work without changing application source code.

Create a clear README section explaining exactly how to configure Google OAuth.
